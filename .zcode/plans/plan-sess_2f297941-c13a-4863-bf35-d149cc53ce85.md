# 更新 geelato-sample-orm：基础 CRUD 增强 + 高级方法演示 + SPI 扩展演示

## 范围与约定（确认）
- 全部改动集中在 **现有 `geelato-sample-orm` 模块**（端口 8082，H2 内存库 `MODE=MySQL`），不新建模块。
- 高级演示全部走 **Fluent DSL `MetaFactory`**（H2 上稳定可靠）。
- 实体 `extends cn.geelato.core.meta.model.entity.IdEntity`（复用 `@Id String id`），加 `@Entity/@Col/@Title`；Fluent DSL 走字段反射，实体无需 getter/setter。
- **SPI 扩展自带实现**：本轻量示例未引入 `geelato-web-platform`，默认的查询过滤注入器与保存字段填充器不存在；故 **在示例内自定义两个 `@Component` 实现** 来演示「过滤器注入/强制注入/DSL 跳过」「默认字段填充」。
- 诚实边界：多数据源 `useDataSource`、字段加密、软删除、事件机制 → 只写进 README（事件指向 `geelato-sample-orm-event`），不做可运行端点。

## Part 3：SPI 扩展演示（新增，用户本次要求）

### 3.1 `spi/SampleAuditFieldValueFiller.java`（新增 `@Component`）
实现 `FluentSaveFieldValueFiller`：
- `isEnabled()` 返回 `true`；
- `fill(ctx)`：按 `ctx.getCommandType()` 与 `ctx.getEntityMeta().getFieldNames()` **实体感知**地用 `targetValueMap.putIfAbsent(...)` 填充：
  - Insert：`createAt=now`、`creator="system"`、`tenantCode="demo-tenant"`
  - Update：`updateAt=now`、`updater="system"`
- 用 `putIfAbsent` → 显式传入的值优先（演示「自动补齐不覆盖业务值」）。

### 3.2 `spi/SampleTenantQueryFilterInjector.java`（新增 `@Component`）
实现 `FluentQueryFilterInjector`：
- `enabled`（默认 true）/ `forceInject`（默认 false）为 `volatile` 字段，带 getter/setter 供端点运行期切换；
- `inject(command, query)`：`entityName = query.resolveEntityName()`，查 `MetaManager.singleInstance().getByEntityName(entityName).getFieldNames()`，**仅当实体含 `tenantCode` 字段**时，取/建 `command.getWhere()`（`FilterGroup`）并 `where.addFilter("tenantCode", "demo-tenant")`；
- `isForceInject()` 返回当前 `forceInject` 值。

> 说明：唯一启用注入器由 `FluentQueryFilterRuntimeResolver` 保证；`disableInjectFilter()` 仅在 `isForceInject()==false` 时跳过（见 resolver 代码），故一个可切换 force 的注入器即可演示「注入 / 跳过 / 强制注入」三种语义。

### 3.3 新增 `web/SampleOrmSpiController.java`（前缀 `/api/orm/spi/`）
- `GET /fill/seed`：插 1 个商品（不传 createAt/creator/tenantCode）。
- `GET /fill/show?id=`：查回该商品，返回 `createAt/creator/tenantCode` 已被 3.1 自动填充（演示默认字段填充 SPI）。
- `GET /fill/update?id=`：`MetaFactory.update(Product).value("name",...).save()`（只改 name），查回展示 `updateAt/updater` 被 3.1 自动补齐。
- `GET /inject/seed`：插 3 个 `tenantCode` 由填充器补为 `demo-tenant` 的商品 + 1 个显式 `tenantCode="other-tenant"` 的商品（`putIfAbsent` 让显式值生效）。
- `GET /inject/status`：返回当前 `enabled`、`forceInject`。
- `GET /inject/enable?on=true|false`：切换注入器 `isEnabled()`。
- `GET /inject/force?on=true|false`：切换注入器 `isForceInject()`。
- `GET /inject/query?skip=true|false`：
  - `skip=false` → 普通查询；注入器启用时附加 `tenantCode='demo-tenant'`，仅返回 demo-tenant 行；
  - `skip=true` → `.disableInjectFilter()`：当 `forceInject=false` 跳过注入（返回含 other-tenant 的全部行）；当 `forceInject=true` 仍强制注入（仅返回 demo-tenant 行）。
  - 返回 `total`、`demoTenantCount`、`otherTenantCount`、`injected` 推断，直观体现三者差异。

## 实现期重点验证（风险点 + 兜底）
1. **`$fn.nowDateTime` 解析**：用 `toSql()` 确认 SqlManager 把 `ValueRefs.fnNowDateTime()` 渲染为 DB 时间函数；若不解析则该值改为显式 `new Date()`，README 保留 `ValueRefs` 片段说明。（注：默认字段填充 SPI 改为直接 `new Date()`，不依赖 `$fn`，更稳。）
2. **H2 `CREATE ALIAS` 存储过程**：确认 `call proc_product_stats(?)` 经 `callForMapList` 能返回多行；若不兼容则该端点降级为 README 文档 + native SQL 等价端点。
3. **注入器 / 填充器实体感知**：确认 `MetaManager.getByEntityName(...).getFieldNames()` 对各实体返回正确字段名；注入 `tenantCode` 与填充 `createAt` 等 field→column（`tenant_code`/`create_at`）映射在生成 SQL 中正确（必要时用 `toSql()` 核对）。
4. **编译与运行**：`mvn -pl geelato-sample-orm -am compile` 编译；`mvn -pl geelato-sample-orm spring-boot:run` 启动后逐个 curl `/api/orm/adv/seed`、`/api/orm/spi/inject/seed` 等端点，验证返回结构与日志（resolver 会打印 `Applying/Skip ... injection/fill` 日志，可佐证 SPI 生效）。
